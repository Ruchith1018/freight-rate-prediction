# Freight Rate Prediction - Spotter ML Engineer Assessment

Predicts `posted_rate` for freight loads and produces a fixed-lane December
2025 rate curve, per `Freight_Rate_ML_Assessment.pdf`.

## Project structure

```
freight-rate-prediction/
├── README.md                          <- you are here
├── requirements.txt                   <- scorer deps + training deps
├── data/
│   ├── train_test.csv                 <- 48,000 labeled loads (Jan-Oct 2025)
│   ├── validation.csv                 <- 12,000 loads to predict
│   ├── validation_predictions_template.csv
│   └── december_chart_inputs.csv      <- 31-day fixed-lane inputs to fill

│   ├── config.py                      <- paths & column constants (single source of truth)
```

## Setup

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` includes the original scorer requirements (matplotlib,
numpy, pandas) plus what the training/prediction code needs
(scikit-learn, joblib).

## Run everything

Command-line (produces the exact submission files):

```bash
python -m src.train      # trains the model, prints holdout metrics, saves models/freight_rate_model.joblib
python -m src.predict    # writes outputs/validation_predictions.csv and outputs/december_chart_inputs_filled.csv
python score.py --predictions outputs/validation_predictions.csv --december-predictions outputs/december_chart_inputs_filled.csv
```

Or open `freight_rate_prediction.ipynb` and run all cells — it's the same
pipeline (same cleaning, same model, same outputs) narrated end-to-end
with EDA plots and results shown inline. It writes the same files to
`outputs/` as the command-line path above, so either one produces valid
submission files; the notebook is best for walking through the reasoning,
the `.py` modules are best for reproducing the pipeline.

## Approach summary

- **Split:** time-based holdout (last ~15% of days in `train_test.csv`), not random —
  `validation.csv` and December are future dates relative to training data, so the
  holdout is built the same way to give an honest generalization estimate.
- **Model:** `HistGradientBoostingRegressor` on `log1p(posted_rate)`, with
  `equipment`/`pickup`/`delivery` as native categoricals and `distance`,
  `weight`, `market_index`, `quote_signal`, lat/lon, and date-derived
  seasonality features as numeric inputs.
- **Data quality handled:** negative/missing `weight` values, missing
  `market_index`, and pickup/delivery cities in `validation.csv` that never
  appear in training data.
- **December file:** lacks lat/lon and market_index/quote_signal columns;
  these are reconstructed (exact city lookup for lat/lon, training-set
  mean for the two weakly-correlated market signals) before scoring.

Full detail, EDA figures, and metrics are in
`report/Freight_Rate_Assessment_Report.docx`.
